# 竞品拆解

不是把竞品夸一遍，而是找出**它守不住的地方**。

## 适用场景

- 准备进入一个类目，先看头部怎么打
- 自家链接被竞品压制，找反击点
- 给新品定价格带、卖点、图片方向
- 写对比型广告/文案

不适用：类目整体评估（用「类目深度评估」）。

## 开工前：先收信息 + 问两件事

**必收**：

1. 竞品 ASIN 或链接（1–3 个，别一次给 20 个）
2. 你的产品、价格、差异点
3. 站点

**必问**（两句话问完，别展开解释）：

```
开始拆之前确认两件事：
① 要不要做广告审计？（查它开了几个广告活动、投哪些词、自然/广告流量占比）
② 要不要查站外痕迹？（TikTok / Reddit / Quora，只能看到公开可见的）
```

- **默认都不做**，用户说要才做。用户没回答就一直按"不做"处理。
- 用户说不要的，`check_output` 的 `skip` 里带上对应章节名（见文末）。


## 拆解维度

### 1. 基本盘

- 价格、Coupon、秒杀、Subscribe & Save、捆绑
- 评分、评论数、上架时间（能看到的）
- BSR / 类目排名（有数据才写，标注日期）
- 变体：颜色/尺寸/套装，哪个变体是主力
- 配送：FBA / FBM / 海外仓，预计送达

### 2. Listing 结构

- 标题：核心词、卖点顺序、字符数、可读性
- 五点：每点在讲什么、利益还是参数、有没有证据
- 描述/A+：场景、品牌故事、对比表、常见问题
- 图片：主图背景、场景图、尺寸图、细节图、对比图、包装图；数一下几张
- 视频：有没有、讲什么
- 评论置顶/QA：官方在回避什么

### 3. 评论护城河

- 评分分布（1–5 星占比）
- Top 差评的 5 个高频痛点
- 好评里被反复提的 3 个购买理由
- 评论增长速度和上架时间的关系（判断是否刷/合并，但不要下结论）
- 退货原因（如果能拿到）

### 4. 流量结构

- 核心关键词覆盖：标题/五点里出现了哪些
- 广告位：搜核心词前 3 页，它出现在哪些位置（需实测）
- 关联流量： Frequently bought together、对比表
- 站外：Deal 站、红人、TikTok（搜得到才写）

### 5. 供应链与成本推测

- 材质/结构/工艺，推测成本区间（标注“推测”）
- 是否容易改模、改包装、改套装
- 专利/认证风险（外观、实用专利需专业检索）

## 输出：一张作战卡（结构固定，不许自由发挥）

**7 个固定章节 + 2 个可选章节。固定章节一个都不能少，顺序不能改。**
抓不到的字段写「未获取」，但**章节本身不能删**。可选章节用户说不要就整节不写。


**交卷前必须调 `check_output`**：把上面这份 Markdown 全文原样传进去。

- 两件都做：`{ content }`
- 用户不要广告审计：`{ content, skip: ["竞品广告审计"] }`
- 两件都不要（默认）：`{ content, skip: ["竞品广告审计", "站外痕迹"] }`

返回「通过」才算完成；返回缺章节或不合格，就按提示补全后**再调一次**，直到通过。

用户要文件时，写成 `reports/<ASIN>-battlecard.md`（内容与上面完全一致）。



## 红线

1. 不编评论数、BSR、销量、上架时间；抓不到就写“未获取”。
2. 不把推测写成事实，成本/专利尤其要标注。
3. 不复制竞品文案、图片、品牌元素。
4. 不建议恶意点击、刷评、合并变体等违规操作。
5. 观察有时效，注明抓取日期。
