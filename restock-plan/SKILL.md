# 备货计划

一句话：**这个 SKU 现在还能卖几天，下一批该备多少。**

不同于「库存与补货」那个通用方法，这个技能是**跑数的**：直接读领星的 SKU 级销量和库存，出一份能贴给老板的 HTML。

## 什么时候用

- 每周/每半月例行盘一次库存水位
- 要下单了，算每个 SKU 备多少
- 判断哪个 SKU 快断货
- 看今年这个月比去年卖得好还是差

不适用：选品、利润测算（用对应技能）。

## 数据从哪来

| 数据 | 来源 | 说明 |
|---|---|---|
| SKU 日销量 | 领星 `query_product_performance_asin_lists`，日粒度、SKU 汇总 | 最近 70 天 |
| 库存 / 在途 | 同一接口行内的 `afn_fulfillable_quantity`、`total_inbound` | 取最新一天 |
| 历年同月 | 同一接口，月粒度，分年查询 | 今年 / 去年 / 前年 |

产品清单（SPU、站点、店铺、父体）**与「亚马逊周报」共用** `amazon-weekly-report/config/products.json`，不用重复录。

## 算法（固定，不靠模型发挥）

```
日销        = 最近 30 天销量 ÷ 30
可售天数    = FBA 可售 ÷ 日销
建议备货    = 日销 × (交期 + 安全天数) − FBA − 在途   （负数按 0）
半月销量    = 自然半月（1–15 / 16–月末）内销量加总
同月同比    = 今年同月 ÷ 去年同月 − 1
```

默认参数：交期 45 天、安全库存 30 天、日销窗口 30 天。
要改就在 `config/settings.json` 里覆盖：

```json
{ "lead_time_days": 45, "safety_days": 30, "sale_window_days": 30, "half_month_count": 3 }
```

## 产出长什么样

`reports/restock-YYYY-MM-DD.html`，结构：

1. **总览**：每个 SPU 的日销 / 可售 / 库存 / 在途 / 建议备货 / 同月同比
2. **每个 SPU 一节**：
   - 半月销量（最近 3 个半月，含日均）
   - 历年同月销量（今年 / 去年 / 前年，带同比）
   - SKU 备货表（日销 / 本月已售 / 本月推算 / FBA / 在途 / 可售天数 / 建议备货 / 风险）

## 红线

1. **不许改数**：所有数字来自接口或按上面公式算，缺数据就写「—」，不猜。
2. **不许改口径**：日销窗口、交期、安全天数只能通过 `config/settings.json` 改，不在报告里临时调。
3. **不许给采购建议之外的指令**：不说「赶紧下单」，只说「按当前日销还能卖 N 天」。

## 两种产出

| 产出 | 用途 |
|---|---|
| `reports/restock-日期.html` | 给人看：总览 + 每个 SPU 的半月销量、历年同月、SKU 明细 |
| `reports/备货表-日期.xlsx` | **给人算**：带公式的表格，填在产/在途/在库，自动算可用数量、总需求、需下单 |

Excel 表结构（和你手写的那张一致）：

```
SKU | 在产 | 在途 | 在库 | 可用率 | 可用数量 | 本月剩余 | 下月 | +2月 | +3月 | +4月 | 总计 | 需下单 | 日销 | 备注
                  ↑ 灰底可改          =SUM(在产:在库)*可用率      ↑ 灰底可改        =SUM(月份区)   =总计-可用数量
```

- 灰底（在产/在途/在库、可用率、各月需求）可以随便改
- 白底（可用数量、总计、需下单）是公式，自动重算
- 需下单 > 0 会变红

## 怎么跑

界面：技能库 → 备货计划 → ① 生成备货计划。

命令行：

```bash
python scripts/restock.py run             # 全部 SPU
python scripts/restock.py run LS-66D38    # 只跑一个
python scripts/restock.py build           # 只用已有数据重出报告（不联网）
python scripts/restock.py doctor          # 检查连通性
```
